# Decisions

Log of significant project decisions. Newest at the bottom.

| Date | Decision | Reason |
|---|---|---|
| 2026-09-29 | Build in-house instead of using Google Forms or a paid mileage app | Custom form system, room to grow into a staff app, fits SCCSC workflows |
| 2026-09-29 | One codebase that works as a website and an installable app | Same features everywhere, no app store needed to start |
| 2026-09-29 | Start as a responsive website; make it an installable app (PWA) later | Get the core workflow in front of the director first; the PWA adds little until then |
| 2026-09-29 | Prototype runs on a built-in database (PGlite) with fake data, using the same migrations and RLS policies as Supabase | $0 and no accounts to set up; deployable as a clickable demo; moving to Supabase is configuration, not a rewrite |
| 2026-09-29 | Next.js 16 + Tailwind 4 + Drizzle ORM | Same stack and versions as the main sccsc site, which Eden already maintains |
| 2026-09-29 | Trips are bundled into a claim when the employee is ready ("bundle when ready") | Mirrors the multi-trip spreadsheet without depending on the still-open pay-period cutoff |
| 2026-09-29 | Sign-in by phone number + text code. Roster match (name + phone) gets in right away; anyone else waits for an admin to approve after checking Paychex | Eden's call. Not all staff have work email, and payroll already has verified phone numbers |
| 2026-09-29 | Look follows the live sccsc.org landing page: Onest + Instrument Sans, `#1D1D1D` text, red-heart eyebrows, brush underline. EB Garamond kept only for the wordmark | Eden asked to match sccsc.org; the brief's fonts were stand-ins |
| 2026-09-29 | Status changes happen only through audited database functions; trips in submitted or later claims are locked by RLS and a trigger | "Audit everything" and "approved records are locked," enforced by the database rather than only the app |
| 2026-09-29 | Reviewers and finance see "Home" instead of a home address | Brief: trip addresses may include home addresses; limit who sees them |
| 2026-09-29 | Until a maps provider is chosen, miles are estimated from saved places (labeled as a demo estimate) or typed in | Provider and cost are still open; the estimate shows the workflow without committing to one |
| 2026-09-29 | The home-trip rule is a setting (allow / flag / block), starting at "flag for the approver" | Open question 3; don't guess the policy |
| 2026-09-29 | Nobody reviews their own claim. A coordinator's own claims go to their coordinator; admins can review anyone's claim as a fallback | Separation of duties; covers people without a coordinator and coordinators who are away (open question 5) |
| 2026-09-29 | Employees can withdraw a submitted claim before it's reviewed (it becomes a draft) | Fix a mistake without asking the coordinator to return it |
| 2026-09-29 | Bulk approval only for claims under a set total with nothing flagged (setting, $100 to start); the server re-checks | "Bulk approve for simple cases" without letting flagged trips slip through |
| 2026-09-29 | Batch export is two generic CSV layouts (trip detail, and totals per employee and program) until the financial system's import format is known. Downloading freezes the batch | Open question 1; freezing keeps the file and the batch in agreement |
| 2026-09-29 | Rules that are guesses live in the settings table: home trips, bulk approval limit, program required, session length, oldest trip | CLAUDE.md: don't guess business rules; make them configurable |
| 2026-09-30 | Real sign-in texts for the demo through Twilio Verify, with every code sent to Eden's phone (`DEMO_SMS_TO`) whatever number is typed | Shows the real text-message flow to the director without texting fake numbers. Verify needs no phone number or carrier registration, a trial account can text verified phones, and Supabase supports it later |
| 2026-09-30 | The demo can email sign-in codes through Resend (every code to Eden's inbox, `DEMO_EMAIL_TO`), in a themed HTML email. Email wins over Twilio when both are set | Free (Resend's free tier) where texts cost money. Staff still sign in by phone; email is only a demo channel |
| 2026-09-30 | Sign-in is by email and code by default, with "Use phone number instead" for a text code. The roster holds both, and one sign-in account per person holds both, so either leads to the same trips | SCCSC isn't paying for text messages for now; email codes are free. Phone stays available for staff who prefer it, once texts are approved |
| 2026-09-30 | Phone bills are the second request type: $45 a month (effective-dated rate), claimed every two months in the even months ($90), one claim per person per month. Months per claim and how far back a missed period can be claimed are settings | Eden's rules; the period length and late claims aren't confirmed, so they're configurable. Built as a flat allowance with no bill upload (open question 19) |
| 2026-09-30 | The app is renamed "reimbursement tracker" (wordmark, titles, sign-in email) | It covers more than mileage now |
| 2026-09-30 | Claim numbers show the type: M-1001 for mileage, P-1002 for a phone bill (one shared sequence) | Finance and coordinators can tell them apart at a glance |
| 2026-09-30 | Eden's own account (real name and work email) is on the demo roster as employee and admin | Eden's request, so Eden can sign in to the demo with a real emailed code. The only real person in the seed |
| 2026-09-30 | Request types are added by migration, not the seed | Every database, including Supabase later, needs them; the seed is demo data only |
| 2026-09-30 | The header links show from 1024px wide; narrower screens (phones and tablets) use the bottom tab bar | With the longer name and the Phone bill link, the header didn't fit at tablet widths for people with every role |
| 2026-09-30 | A phone bill claim needs a photo or PDF of the bill (answers open question 19). Enforced in the app and by a deferred database trigger | Eden's rule. The trigger means even a bug can't send a claim without the bill |
| 2026-09-30 | Bill files are stored in Postgres (`request_attachments`, bytea) with the claim's visibility, typed by their contents, up to 5 files and 4 MB per upload, with big photos shrunk in the browser | Works the same in the demo and on Supabase with no extra service. Vercel caps requests at 4.5 MB, and phone photos are often larger. Moving to Supabase Storage stays an option (M7) |
| 2026-09-30 | Direction for the staff hub (later): home base (announcements, documents, links, calendar), more request types, a trainings and documents tracker run by Recruitment staff, Resend email reminders they control, other languages, and Paychex linked rather than copied | Eden's priorities, so the app becomes the place staff check often. Recorded in the brief (section 5) and milestones M10 to M14 |
| 2026-09-30 | New-hire onboarding stays in Paychex; timekeeping is set aside | SCCSC already onboards in Paychex. Timekeeping would make the app the official timecard, with California overtime, break and record rules; not worth it before those questions are answered |
| 2026-09-30 | An opening animation of the full SCCSC logo on white, about 3 seconds, once per browser tab; a tap or Escape skips it, and it's off when a device asks for reduced motion | Eden's request. Once per tab (not every page or reload) keeps it from slowing staff down, and people sensitive to motion never see it |
| 2026-09-30 | The full "thecenter" logo is traced to vector (`assets/brand/thecenter-logo.svg`) from Eden's original artwork, and the animation is CSS on that SVG, with no animation library | Sharp at any size, no extra dependency, and the letters can move one by one. It also replaces the small PNG on printed claims |
| 2026-09-30 | In the opening animation, the "sacramento chinese / community service center" lines are text in Instrument Sans (weight 500) instead of the traced serif, in the same two-line placement | Eden found the small serif hard to read. Instrument Sans is already the app's text font (from sccsc.org), so nothing extra loads, and the intro's logo data halves |
| 2026-09-30 | The opening animation starts with the seal large in the middle of the screen, then glides it into the logo | Eden preferred it to the seal starting in place |
| 2026-09-30 | "thecenter" in the opening animation is live EB Garamond text, one letter per element, placed from the font's own spacing and kerning where the original logo has the words | Eden identified the logo's typeface as EB Garamond, already loaded for the wordmark. Real text is sharp at any size, and the intro's logo data drops to the 心 strokes (4 KB) |
| 2026-09-30 | The opening animation goes back to the seal stamping in at its place on the left (the centered start, where it glided over, is in the history) | Eden's choice after seeing both |
